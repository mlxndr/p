## Overview

A static academic presentation platform built on reveal.js 5.2.1, hosted on
GitHub Pages at `mga.is`. Each presentation lives in its own folder and is
authored in markdown. There is no build step: files are served as they are,
and everything (markdown loading, directive expansion, theming) happens in
the browser. CI: `.github/workflows/build-manifest.yml` regenerates
`manifest.json` (used by the landing page, and its `series` lists by the
series index pages) from each folder's `meta.json` on push; `.github/workflows/slides-pdf.yml` exports each changed deck to
`<deck>/slides.pdf` (DeckTape, 1920x1080, fragments shown, spares at the
end, `pdfTheme` if set) and `<deck>/slides-handout.pdf` (the student
version, two slides to an A4 page, via `scripts/handout-nup.py`), and,
where the deck has a handout.html, `<deck>/text-handout.pdf` (the text
handout, student version) and `<deck>/notes.pdf` (the notes in two
columns, full copy), printed by headless Chrome with
`scripts/text-handout-pdf.js`; it can be run by hand to rebuild every
deck after inc/ changes.

Test locally with any static server, e.g. `python3 -m http.server 8000`,
then open `http://localhost:8000/research/icame47/` (or any deck's folder). Deployment is automatic
on push to main.

## Authoring slides

Slide separators in content.md: a blank line then `---` for a new
horizontal slide, `--` for a vertical slide, and `notes:` at line start
for speaker notes. Markdown lists animate in as fragments (animateLists).

### Image directives

Images and image transitions are authored with @-directives, one per line,
expanded in the browser by `inc/directives.js`. Options are `key=value`,
`key="quoted value"`, or bare flags. `alt=` is expected on everything; a
missing alt renders a red ribbon on the slide until fixed. Every generated
slide gets a stable `id` from the image filename, so deep links like
`#/mirror1834-06-03` survive editing; override with `id=`.

```
Full-bleed image slide (contain by default, never crops charts):
  @image ./img/chart.png alt="Description" caption="Optional caption"
  @image ./img/photo.jpg alt="..." fit=cover focus=30,60

Text over the image (the markdown after it, to @end or the end of the
slide; positions top-left, top, top-right, left, centre, right,
bottom-left, bottom, bottom-right; the body may hold @columns):
  @image ./img/photo.jpg fit=cover alt="..." over=top-right [band|bubble] [dim] [build]
  > *Te magister artium creamus*
  @end
  (no style: a paper panel; band: a dark band to the screen edges;
  bubble: a speech bubble; dim: a veil of the paper colour over the
  image; build: text and veil arrive on a click)

A run of full-bleed slides (one indented line each):
  @image-seq
    ./img/chart1.png alt="..." caption="..."
    ./img/chart2.png alt="..." caption="..."

Image + text columns (markdown after the directive = text column;
split= sets the image column percentage, default 42):
  @image-left ./img/portrait.png alt="..." split=38
  * first bullet
  * second bullet

  (@image-right mirrors it; add `build` (or the old `fragment`) to reveal
  the image on click; `bleed` runs the image to the screen edge, cropped,
  with focus=x,y choosing what the crop keeps, and a heading written
  before the directive moves into the text column; the text column
  takes directives (@columns, @cards, @note ...); a @source goes after
  the split)

Two images side by side:
  @compare
    ./img/before.png alt="..." caption="Before"
    ./img/after.png alt="..." caption="After"

Hold an image steady while the text swaps (auto-animate pair — put the
same directive with the same id on two adjacent slides; works on @image
and @image-seq lines too, which then draw the image in the slide frame,
and the file may change between the two):
  @image-left ./img/scan.png hold id=ocr alt="..." split=42

Zoom from a full image into a detail that fills the screen:
  @zoom ./img/page.png focus=28,38 scale=3 alt="..." caption="..."
  focus = the point on the visible image (percent across, percent down)
  that ends centred; scale = magnification. Add to=./img/crop.png to land
  on a sharper pre-cropped file instead (focus/scale then unnecessary).

Ken Burns background (use sparingly — section dividers and image-only
slides, never under content the audience should read):
  @kenburns ./img/photo.jpg alt="..." pan=in dur=24s
  pan: in, out, left, right, up, down. Honours prefers-reduced-motion.

Marks on an image, one step (click) per line; positions in percent of
the image; the image stands alone first:
  @marks ./img/map.png alt="..." [caption="..."] [all]
    ring 47,52 r=8 green "Dutch" [pos=above|below|left|right]
    + ring 44,45 r=4 gold "West Frisian"     (+ joins the step before)
    box 10,20 w=30 h=12 red id=b1             (x,y = top left)
    box 40,20 w=30 h=12 id=b1                 (same id: the box moves there)
    label 20,80 "Very frequently used" teal rot=-80
    dim y=40,55 | dim x=10,30 | dim 10,20 w=30 h=12   (darkens the rest)
    zoom 40,40 2.5                            (zooms in as a step)
  r= is a percentage of the image width (w= h= instead for an ellipse);
  all: every mark at once. Add ?coords to the address and click an image
  to see (and copy) the position of the click in percent.

Captions on every image directive take *italic* and **bold**
(book titles, species names); nothing else in them is markdown.

Video (a click plays it once and it stops on its last frame; markdown
after it becomes a side column as with @image-left; the poster is what
the PDF shows; the file is kept for offline use):
  @video ./media/clip.mp4 poster=./img/clip.png alt="..." [split=66] [caption="..."] [autoplay] [loop] [muted]
```

### Text-slide directives

```
Slide modifiers (expand to classes; combine flags freely):
  @slide smaller            85% text (smallest = 72%) for dense slides
  @slide centred            vertically centre short content
  @slide plain              no heading rule
  @slide spare              after the closing slide, uncounted
  @slide contrast           the theme's title ground carries the slide
                            (cream text on Terracotta, white on Slate,
                            etc.); bg=#hex overrides
  @slide fade | cut         transition into this slide (cut = none)
  @slide hidden             kept in the source; not in the show, PDF or
                            handout (reveal's data-visibility="hidden")
  @slide nohandout          shown, but left out of the student version
                            and the handout (hidden and nohandout apply
                            to every slide the chunk makes, e.g. all of
                            a @zoom's slides: carrySlideFlags)
  @slide static             nothing builds unless marked (click marks,
                            @pause, @note build still do)
  @slide build              lists build here even in a listBuild:false deck
  @slide build=auto         the slide's builds run without clicks (0.9 s
                            apart), stopping when the slide is left
  @slide build=all          every block after the heading arrives in
                            reading order (paragraphs, h3s, tables, list
                            items one by one); a block with builds of its
                            own (a table of answers) arrives, then those
                            builds; a block that is only a list (@columns
                            flowing one) takes no click of its own; menus
                            and source lines stay put
  @slide morph              auto-animate from the slide before (written on
                            this slide only); words: every word a piece
                            (words=loose ignores punctuation and case);
                            duration=1.5 (seconds; default 1)
  @slide morphemes=split    the state of every morpheme word on the slide
  @slide statement          one large centred sentence or quotation; a
                            paragraph given class md-gloss (an element
                            comment, e.g. a paraphrase above and below)
                            is set centred at body size
  @slide activity           room activity: lighter ground, accent bar at
                            the screen edge (not used in Marc's lectures:
                            leave it out when converting)
  @slide shrink=N           this slide may shrink to fit down to N% (40 to
                            100) instead of 72% (corporate: 70%)
  @slide text=N, placeholder, textbox   corporate decks: body size in
                            pt; the template's content placeholder or a
                            text box (see Corporate mode)
Part divider (one centred display heading; shows the deck's series
line above it when meta.json has "series"; ` :: colour` after the text
is the card colour in corporate mode, where the markdown below it goes
on the card):
  @section Part Two: The Corpus
Heading with a smaller second line:
  ## Silly | from 'blessed' to 'foolish'      (\| for a literal bar)
Sidenote options (after ` :: ` at the end; a ` :: ` followed by anything
other than these stays part of the text, so glosses are safe):
  @note Each step is a sense attested in the OED. :: top build
  (top: straight after the heading; build: a click of its own)
  @note Look out for conjunctions! :: float
  (float: a reminder box at the foot of the slide, centred, out of the
  flow, so the content above does not move between step slides with
  and without it; shows from the start unless build)
Source line (small, upright, subtle, right-aligned; markdown allowed;
replaces <p class="md-source">, which still works; after a displayed
quotation, a left-aligned source starts where the quotation's text
does; the block after a source keeps a gap):
  @source *OED Online*, s.v. *silly*, adj.
Group builds: everything after @pause, up to the next @pause or the end
of the slide, appears on one click as one piece (lists included):
  @pause
Insert another markdown file (relative to the including file; nests;
a cycle or missing file is an error slide; cached for offline use):
  @include ../shared/sets.md
Displayed quotation (body of the chunk = the quote, markdown allowed):
  @quote attrib="W. E. Gladstone, HC Deb 20 April 1877" [contrast] [card]
  '...the primary record, and not *Hansard's Debates*...'
  (card: the quotation on the turned-corner card)
  Quotation marks hang into the margin; a quotation (or a split
  layout's text) that does not open with a quotation mark is set flush
  (unhangQuotes adds md-no-hang).
The turned-corner card, a callout for anything (a transcript, an image
with text, notes), to @end or the end of the slide; each form draws its
own, the other themes a plain one:
  @card
  @transcript
    a: Are you doing anything on Friday?
  @end
Example sentences on a card (the card's list has no markers and builds
as usual; a sub-item or a %%aside%% is a note in the body face; plain
lines keep their line breaks):
  @card ex
  * He **awoke** in the night and **discovered** he **loved** grammar.
    * Note the commas: ...
  @end
  The examples are set in the form's contrasting face, --ex-font (a sans
  in a serif form: Concourse in Plate and Key, Thumb Index and Fair
  Copy; a serif in a sans one: Bitter in Attested Forms, Lantern Slide
  and Quiet Index), scaled by --ex-scale; other themes keep their own
  face. [Bill is happy.]{ex} sets an example inline (class md-exs) in
  the same face, for examples inside a list.
References (hanging indents, smaller, list items never fragment):
  @refs [title="References"]
  * Knight, C. (1865) *Passages of a Working Life*. London.
Inline styling in any markdown text:
  ^^oed^^ renders as real small caps (replaces the hand-written
  <span style="font-variant: small-caps;"> pattern)
  %%an aside%% renders in the theme's subtle text colour
```

### Sets, tags and menus

```
Define labelled items once per deck (or per course, in a file pulled in
with @include): Label :: colour :: icon :: optional. Aliases go
comma-separated in the label; every field but the label may be left out.
A set shows nothing where it is written, and a slide holding only sets
is dropped.
  @set criteria
    Orthographic, Spelling :: green :: pen-nib
    Phonological :: teal :: volume
  @set languages text               (a text set: names in a colour)
    Latin :: blue
    Greek, Hellenic :: green

Uses:
  [[Orthographic]]      the set's tag: a pill in its colour with its icon
  ## [[Orthographic]]   a heading that is one tag is a ribbon heading
                        (on a morph slide the tag moves into it)
  [[Latin]]             text set: coloured text, no pill; names from a
                        text set are also coloured with no markup in
                        @tree and @marks labels
  [[GPA 9.0]]{grey}     a tag outside any set takes its colour in braces

Navigation drawn from a set; it holds still across slides, and
consecutive slides with a menu of the same set morph by themselves:
  @menu neologisms all centre       every item lit, at mid-slide
  @menu neologisms labels           all lit, labels arrive on a click
                                    (labels=static: at once)
  @menu neologisms 2                item 2 lit, the rest grey; also 4,5
  ## Conversion                     the heading sits under the lit item
                                    and moves along (heading=build on the
                                    menu: it builds in on a click instead)
  @menu honours 2>3                 steps: the arrow between 2 and 3 lit
  The heading aligns with the lit item's nearer edge; a form that sets
  --menu-head-align: centre on .md-menu-head centres it under the item.
  Thumb Index hangs the heading under a strip's lit item on a stem:
  positionMenuHeads centres it in pixels, inside the side margins, and
  a morph slide with the same item lit keeps the slide before's left
  edge (so Abbreviation to Abbrev. changes in place). Autofit never
  zooms a menu.
  style=strip (circles with icons; the default when every item has an
  icon), tabs (a stack of ribbon tabs, plain rectangles), steps (boxes with arrows; the
  default otherwise). Icons must have a codepoint pair in base.css
  (any icon in the licensed font may be added; see Fonts).
```

### Morph

`@slide morph` on a slide makes reveal's auto-animate run from the slide
before (linkMorphSlides in directives.js marks that slide). Identical
headings, paragraphs and images match with no markup; `[[pieces]]` match
by text or id; `words` makes every word of both slides a piece. Menus,
morpheme words sharing pieces, `@zoom`, `hold` and `@transcript
morph`/`overlay` morph by themselves; an explicit `@slide fade` or `cut`
stops the automatic links. The matcher (mgaMorphMatcher, passed to
reveal as autoAnimateMatcher) leaves out of matching anything that builds
in on the new slide, and moves words and morpheme pieces without scaling
them; elements of the old slide with no partner fade out
(ghostUnmatched). Export (`?fragments=false`, print) turns auto-animate
off, so every slide is captured in its final state.

Morpheme words are an inline mark: ` + ` between the pieces, a hyphen on
the affix side, the state after the bracket.

```
  [un- + help + -ful + -ness]{plain}    the word, pieces coloured
  [un- + help + -ful + -ness]{split}    pieces apart, with their hyphens
                                        (also apart: no hyphens; bases,
                                        affixes: the other kind dimmed)
  [un- + help + -ful + ~-ness]{jigsaw}  puzzle pieces; ~ hides a piece
                                        but keeps its id, so a morph
                                        fades it out
```

Pieces are coloured by their text: each new piece in a deck (un-, help,
-ful) takes the next colour of a cycle and keeps it wherever it appears
again, so -ful is the same colour in unhelpful and lustful. Ids come from
the word and the piece, so the same word on adjacent slides morphs.

### Text blocks

Each is a registered directive (directives.js, "text blocks (SPEC 4,
phase 2a)"); the styles are the "Phase 2a: text blocks" section of
base.css, with compact versions at the end of handout.css. Where a block
builds, `?fragments=false` shows its final state.

```
Cards and columns (markdown body, cards separated by `::` lines, closed
by @end or the end of the slide):
  @cards [cols=N] [widths=62,38] [style=box|plain|bar|header|stat|strip]
         [height=auto|fill] [h= text= head= radius=  (px)] [arrows] [stack] [build]
  ### Heading
  text
  :: light-blue foot icon=chalkboard-teacher
  ### Next card
  @end
  Card flags after `::`: a palette colour (strong colours take white
  ink), icon=NAME, disc=COLOUR (the icon on a disc of that colour,
  beside the heading), wide, accent, dim, foot (pinned to the card's
  foot), answer, build. A first line [[TAG]]{colour} becomes the card's
  tag.
  @columns is @cards with style=plain by default; @columns cols=2 with no
  `::` lines flows the content into CSS columns (cols only); a single
  list is laid out filling each column in turn (md-flow-list, a grid),
  so the columns start level in every browser.
  style=bar: the card colour fills a heading bar. style=header: the colour
  fills a rounded header holding the ###, centred, and the text sits
  below it with no box. style=strip: two cards, the
  first holding tokens on one line (`A3, B2, C1, ~~D3~~ C3`), the second
  the text; `{~~D3~>C3~~}` as a token keeps D3 struck through beside C3
  after a click, at the pair size, and every replacement in one strip
  changes on the same click. arrows: an arrow between cards; stack: one per row, centred,
  each card wider than the one above (arrows point down). height=fill:
  the cards stretch to the slide foot. Autofit works inside cards and
  columns. In corporate mode a block takes the body's free space unless
  height=auto is written out (a band above or below the main cards).
Horizontal rule between blocks (--- would end the slide):
  @rule [COLOUR] [build]
Terms (item lines):
  @terms [sc] [build | build=columns] [answers]
    hovercraft :: hover + craft
  build: a row per click; build=columns: every term a click each, then
  every gloss; answers: glosses are answers (one click; hidden in the
  student version).
Statistics:
  @stats
    96% :: Fewer files :: 83 files to 3          (number :: label [:: note])
Numbered examples (numbering runs through the deck):
  @ex [numbers=off] [start=N] [name=x]
    The dog eyed the birthday cake. :: canonical order
    *a five beautiful days           (* ? ?? # judgement marks; a line
    (b) A hand-set label.             starting *word* is italic, not a mark;
    ?Colourless green ideas.          a hand label does not advance the count)
    text :: (N)                       (a field wholly in parentheses is a tag)
  `@ex x` later repeats a named block with its original numbers.
Table formatting (prefix for the markdown table that follows):
  @table [head=COLOUR] [band] [rowhead] [caps] [small] [bars] [build] [widths=22,26,26,26]
  A header row of empty cells is hidden. widths= are preferred
  percentages; a cell never shrinks below its longest word.
  bars: a cell ending in "(N%)" gets a bar of that length beneath its
  text where the form draws bars (Plate and Key); elsewhere nothing shows.
  build: body rows arrive one per click, the table laid out full size
  from the start. {++x++} in a cell opens out without widening the
  column.
Concordance (KWIC):
  @kwic [build=context] [prose] [window=N]
    the hammer was used to | strike | the nail into the wall
  \| for a literal bar. build=context: nodes first, contexts on a click.
  window=N (1 to 8): N words either side in position columns (-3 ... +3).
Trees (indented item lines):
  @tree [style=diagram|outline] [big] [build | build=level | build=up]
    FTA
      commit the FTA
  diagram: brace diagram; outline: `code :: label` rows. build is
  reading order, build=level one level per click, build=up the leaves
  first. big: 1.2 times the size, for a tree that is the slide. A node
  that is one set tag ([[Free]]) is drawn as a tinted block with its
  icon, at the text's size.
Transcripts (conversation analysis):
  @transcript [numbers] [mono] [overlay] [morph] [build]
    a: Are you doing anything on Friday // evening?
    b: // Nothing much, why?
    (1.0)
    b: Well (0.5) I'd like to       (a line with no label continues the turn)
    note :: a: text                 (a margin note before the label)
  Labels are up to 12 characters, no spaces. Each speaker's lines carry
  md-tr-spk-N (N in order of first appearance), for forms that tell
  speakers apart. `//` marks overlap onset;
  a turn starting with `//` lines up under the first onset above. A
  pause line takes the step of the turn after it. overlay: the panel
  slides up over a faded copy of the slide before (put the transcript on
  its own slide after the slide it covers; consecutive overlay slides
  hold still, in either direction) and slides back down when the slide

  that share lines.
```

### Inline marks

One pass in directives.js (inlineMarks) turns these into spans before
marked runs. The rule: a brace on its own happens on a click; a brace
straight after a closing bracket styles the bracketed text.

```
  ==x==            highlight (--r-highlight; light-gold by default)
  [x]{name}        text in a palette colour; {accent} = the theme accent
  [x]{ex}          an example sentence, in the form's example face
  [x]{italic}      italic in the running face (Attested Forms sets
                   *x* as a cited form; this is for a term or emphasis)
  [S x]            grammar function: S P O Od Oi C Cs Co A cj, then a
                   space. Colour at the text's own weight (bold with
                   **[S x]**); Od/Oi take the object colour, Cs/Co the
                   complement colour; cj is bold in the ink, no hue (as
                   in the MandS colour-coded passages)
  [[x]]            morph piece (span with a stable data-id from its text)
  [[x|id]]         piece with a hand-set id
  [[x]]{name}      tag pill in a palette colour (also a piece)
  :fa-name:        Font Awesome icon (must be in base.css's subset)
  {==x==}          highlight on a click
  {++x++}          inserted on a click (the line opens out)
  {--x--}          removed on a click (the line closes up)
  {~~a~>b~~}       a replaced by b on a click
  {answer x}       a click step when presenting; hidden in the student
                   version (export page, phase 5)
  [a- + b]{split}  a morpheme word (see Morph above)
```

A word starting with a hyphen (an affix: -ness, -mageddon) never breaks
after its hyphen: joinAffixHyphens (directives.js, MgaBuilds.init) puts a
word joiner (U+2060) between the hyphen and the letter in the rendered
slides. Not in corporate mode.

Every paired mark needs a non-space just inside each marker (`a == b`
stays literal). Static and colour marks nest (`==^^x^^==`,
`[S [The army]{accent}]`); click marks do not nest in each other. Not
read as marks: code spans and fences, HTML tags and comments, link
destinations, backslash escapes (`\[A treatise ...]` for a prose bracket
starting with a grammar code), and anything between `<!--md-raw-->` and
`<!--/md-raw-->`. Unknown colour names stay as typed; local preview logs
them, grammar marks longer than eight words, and icons missing from the
subset. Export with `?fragments=false` adds `html.mga-final`: removed
text shows struck through and inserted text in the accent, so the
starting state stays visible.

### Palette

`--p-NAME` and `--p-light-NAME` in base.css for red, orange, gold, green,
teal, blue, navy, purple, pink, grey, plus `--p-white`, `--p-black` and a
darker partner `--p-NAME-deep` for each. One palette for every theme:
white on each strong colour, and each strong colour as text on every
light paper, read at 4.5:1 or better; dark ink on each light colour at
12:1 or better. dark.css draws colour marks in the light versions. The
UoG brand names (dark-red, dark-blue, light-yellow, university-blue
...) are accepted as aliases. Grammar colours (--g-*) are separate and
unchanged.

### Directive parser for new directives

New directives register with `registerDirective(kind, spec)` in
directives.js instead of adding a branch to expandChunk. The spec gives
the body kind (`line`, `items`, `markdown`, `prefix`) and the options;
the shared parser checks the line (positional values, key=value,
comma lists, colours, numbers, `steps="..."` sequences, flags, `build`
and `build=`), collects the body (item lines with ` :: ` fields and
depth; markdown up to `@end` or the end of the slide, with `@slide` and
`@source` lifted out; the next block for prefixes), handles `name=` and
repeats (`@terms blends answers` repeats the block named blends with
merged options), and turns every failure into the red error slide. The
comment above registerDirective documents the spec fields. A stray
`@end` is an error slide.

Escape a literal line-initial `@` with `@@`. Raw HTML and reveal's
`<!-- .slide: ... -->` / `<!-- .element: ... -->` comments still work as
an escape hatch. A malformed directive renders a self-describing red error
slide in preview rather than failing silently.

Utility classes for sizing without inline styles: wrap in
`<div class="md-small">` (70% text, for tables/references) or use
`<p class="md-source">` for right-aligned source attributions.

### Deck metadata (meta.json + inc/site.json)

inc/meta.js generates the title slide, the closing slide (including the
QR code, whose URL derives from the folder path) and the browser-tab
title from ./meta.json merged over the site-wide defaults in
inc/site.json. Merging is per-field: a key present in meta.json wins,
an omitted key inherits the default (author, affiliation, email, logos,
baseUrl). Fields:

```json
{
  "title": "The Fairest in the Land?",
  "subtitle": "Verbatim ... | in the *Mirror of Parliament Corpus*",
  "date": "May 2026",
  "event": "ICAME47",
  "location": "Koblenz",
  "logos": ["leverhulme", "uog"],
  "authors": [
    { "name": "Marc Alexander", "affiliation": "University of Glasgow",
      "email": "marc.alexander@glasgow.ac.uk" },
    { "name": "James Balfour", "affiliation": "University of Glasgow" }
  ]
}
```

`*...*` italicises, `|` forces a line break in title/subtitle,
`^^...^^` sets small caps (acronym events); `"closing": false`
suppresses the generated closing slide, `"closing": "title"` repeats
the title slide instead. Further keys: `"series": "English Words |
history, meaning, and structure"` (a small-caps series line above the
title, on @section slides and in the handout header); `"advisory":
["Swearing and taboo words %%(quoted data)%%"]` (an advisory slide after
the title and a note on the landing page; none unless asked);
`"listBuild": false` (lists appear whole; default true, corporate
false); `"buildStyle": "appear"` (builds arrive instantly; default
fade, corporate appear); `"transition": "fade"` (deck default: none,
fade, slide, convex, concave, zoom; corporate none); `"lockTheme"` and
`"pdfTheme"` (see Theming). A deck with exactly ONE logo
takes a restrained title variant automatically: sentence-case title,
event and date as the subtle line beneath the names, the logo alone
on the right; with a series line too, the logo sits at the top right,
level with the series (the teaching decks). Teaching decks write the
series as "English Language & Linguistics 1^^A^^ | Meaning and
Structure" (course above, lecture series below) and set "closing":
false (lectures go to Moodle, so no QR slide). Use
`author` (string) for the common single-author case; `authors` for
co-authored decks. `logos` maps to the registry in inc/meta.js
(leverhulme, uog, ht) — add new logos there. Logos are always declared
per deck (site.json's default is []): an omitted logos key means none. A deck wanting a bespoke
opening keeps a title.md data-markdown section instead of the
data-meta="title" placeholder; both mechanisms coexist.

### Spare slides

`@slide spare` on a slide moves it after the closing slide (split out of
the markdown in extractSpares, directives.js, into its own section) and
marks it data-visibility="uncounted", so it is left out of the slide
count and progress bar but stays reachable from the menu or by id.

### Autofit

A text slide whose content runs past the bottom of the stage shrinks
automatically (everything except its heading, in 4% steps, via CSS zoom,
floor 72%). A slide that still overflows at the floor gets a console
warning and, in local preview, a red dashed outline: split it. Opt a
slide out with `<!-- .slide: data-autofit="off" -->`. Image layouts keep
their own autofit (split text columns); title slides and @section
dividers are never scaled.

## Export

`?export` on a deck's address opens the export page in place of the
slides (head.js reads the options into `window.MGA_EXPORT`;
script-loader.js loads `inc/export.js`); the menu's top band links to
it ("Export"). It offers: the slides for printing, final state or a page
for every build; a handout of 1, 2, 3 or 6 slides to an A4 page, framed
and numbered, optionally with lines for notes; the text handout
(`handout.html`, where the deck has one); the source files (content.md,
meta.json, title.md, every `@include`d file); links to the CI's
`slides.pdf`, `slides-handout.pdf`, `text-handout.pdf` and `notes.pdf`
where they exist. Theme and palette
are chosen on the page (default `pdfTheme`, else the deck's theme);
corporate decks print in the template.

The print views are reveal's print mode (`?print-pdf`) with these
options: `fragments=false` (final state), `builds=1` (a page per build:
`pdfSeparateFragments`), `handout=1|2|3|6`, `lines=1`, `student=1`,
`spares=0`, `paper=1`, plus `theme=`/`palette=`. A bar at the top (not
printed) holds the Print button, enabled once pages, fonts and images are
ready, and says which paper and orientation to choose; then refitSlides
is frozen (`MGA_PRINT_FROZEN`), since the print dialogue resizes the
window. Handout sheets hold reveal's pages scaled with `zoom` (a
`transform` made Chrome shrink every sheet). Each printed
page takes `.reveal`'s ground (the themes paint it there; reveal copies
the body's, which printed dark themes white). In print a slide keeps the
slide's height and `--bleed-x/y` are the page margin; Spine's padding is
restated for print (reveal's print CSS clears section padding).
Per-build pages: `@marks` re-applies its marks on `pdf-ready`; video
cues and `@refs` items take no page.

The student version (`student=1`; the default in `handout.html`, where
`?student=0` gives the full copy) removes `@slide nohandout` slides and
blanks answers (`{answer x}`, `@terms answers`, a card's `answer`): an
answer stops being a build and keeps its space, inline answers as a
ruled blank. `spares=0` leaves out spare slides (`handout.html` leaves
them out unless `?spares=1`). Hidden slides never appear. Corporate
decks have the slide handouts but no text handout.

The text handout (phase 8b; `handout.html`, `inc/handout.js`,
`inc/css/handout.css`). Each slide is rendered with the slides' own
expander, then merged into a document: slides under the same heading
become one numbered section (a slide with no heading joins the section
before); every build shows its final state (a held image, `hold id=`,
keeps only its last frame, wherever its run ends; a list or transcript
that grows keeps its longest version; a block repeated on a later slide,
or retitled on the next, appears once); image slides become figures,
numbered in reading order and captioned with their caption or else
their alt text (so write both); consecutive figures share a row;
`@section` is a part heading; `@refs` go at the end; menus, overlay
copies, hidden and spare slides and speaker notes are left out, and
`@slide nohandout` slides too in the student version (use it for
atmosphere images and anything that only works in the room). Two
styles: the handout (default; Equity, one 116 mm column with a 48 mm
margin holding figure captions, sources and split-layout pictures, the
space students write in; the student version unless `?student=0`) and
the notes (`?style=notes`; two columns, sources as numbered notes at
the end, compact, for revision; the full copy unless `?student=1`).
handout.js lays the document out on its own A4 sheets, each with a
running head (series and title) and "N of M": WebKit prints no `@page`
margin boxes and repeats no fixed elements, and CSS columns print
wrongly there, so the notes' two columns are two boxes the script fills
in turn. Lists and tables split across pages, headings and part titles
never end a page or column, a quotation keeps its attribution, a short
line before an `@parse` analysis stays with it, answer blanks are at
least 30 mm wide. Sheets are 1 px short in WebKit. The page adds
`html.mga-print-ready` when laid out (wkprint and CI wait for it) and
a bar on screen (not printed) with the other style and Print. Every
handout.html loads handout.css and handout.js as `?v=8b`: bump it in
all of them when either changes (Safari keeps old copies).

Paper and Safari (phase 8). Slide-shaped pages (2073 x 1166 px, from
reveal's `@page` rule) come only from Chrome's Save as PDF. Printing to
paper, any browser lays a page out between the paper's width and 1.5
times it and cuts off the rest, so a slide page lost its right-hand
fifth on A4. `paper=1` (the export page's "On paper, A4 or Letter")
puts each page on a sheet 1152 px wide (`.pp-sheet` > `.pp-slot`,
`layoutPaper` in export.js), a width that fits A4 and Letter either way
round, one sheet to a printed page, the slide 83 px from the top
(centred on landscape A4), white paper round it; reveal's `@page` size
is replaced by `@page { margin: 0 }`. Neither browser tells CSS the
printed page's height (in WebKit `100vh` in print is the window's).
WebKit (Safari, and any browser without "Chrome/" in its user agent:
`MGA_WEBKIT`, `html.mga-webkit`) ignores a CSS page size and offers
only real paper, so head.js sets `paper=1` for every WebKit slide view.
WebKit print faults handled in export.js and export.css, WebKit only,
so Chrome output is unchanged: a sheet exactly the paper's height
gains a blank page after it (handout sheets are 1 px shorter);
gradient stops lose their transparency (a transparent stop prints
black) and CSS masks do not print, so `flattenForWebKit` repaints every
gradient with see-through stops blended over the colour behind it
(card corners and folds, accent bars), drops gradient masks (the
concordance fades), and export.css redraws the arrows between cards
and brace trees with clip-path and borders; a transform inside a zoomed
element is ignored and a zoomed element inside a transformed one is
laid out wrongly, so a page holding `@marks` is scaled with a transform
and every other page with `zoom` (`scalePage`). `vw`/`vh` in WebKit
print are the window's, so images capped by them (the old `66vh`) can
print smaller than in Chrome. Test WebKit printing with the headless
printer `wkprint` (994 Agents/2026-10-30-mga-slides-build/phase8/tools;
it reproduces Safari's PDFs exactly), never by guessing. export.css and
export.js load with a version in their address (`MGA_EXPORT_V`, set in
head.js, `?v=8`): Safari kept an old export.css with a new export.js,
so bump it whenever either changes.

## Theming

The theme catalogue lives in `inc/head.js` (`THEMES`: sections of
{key, name, file}); the menu's Themes panel and its section headers are
generated from it. head.js writes the `<link id="theme">` synchronously,
so there is no flash of a default theme. Opening theme, in order: a
`?theme=KEY` URL parameter (this visit only, never saved); the visitor's
saved choice (localStorage `theme`, written by script-loader.js whenever
the menu changes theme, shared across all decks); the deck's `"theme"`
in meta.json (or `<html data-theme="KEY">`); the default, Terracotta. A saved theme that is
no longer in the catalogue is forgotten. `"lockTheme": true` (with a
`"theme"`) skips the saved choice, High Accessibility included: the
deck always opens in its own theme, and a theme picked from the menu
there lasts for the visit only (script-loader.js does not save it).
`"pdfTheme": "cream"` replaces the deck's theme in export
(`?fragments=false`, `?print-pdf`) unless the URL names a theme. Filenames stay fixed because
saved choices point at them.

### Forms and palettes (phase 5B)

A form is a theme that takes all its colour from a palette. Forms are
the "Forms" section of the catalogue (`form: true`, with a default
light `palette` and a suggested `dark` one); they open and save like any
theme (`?theme=plate`, `"theme": "plate"`, `pdfTheme`, `lockTheme`).
Each form file @imports base.css and palettes.css and then sets type
and devices, drawing every colour from the palette roles (`--pal-paper`,
`--pal-ink`, `--pal-ink2`, `--pal-rule`, `--pal-accent`, `--pal-mark`,
`--pal-accent-ink`, `--pal-on-accent`, `--pal-tint` (the current
column), `--pal-quiet` (the other columns), `--pal-section`,
`--pal-on-section`, `--pal-series`, the card roles `--pal-card`,
`-card-ink`, `-card-ink2`, `-card-accent`, `-card-fold`,
`-card-highlight`, and `--pal-highlight`, `--pal-highlight-ink`).

The palette is a class on `<html>`: `pal-NAME` plus `pal-light` or
`pal-dark` (and `mga-form`); the mode blocks in palettes.css map the
framework's own variables (paper, ink, contrast pair, highlight, logos,
the dark grammar set, the light colour marks on dark). Light and dark
differences in a form go under `html.pal-dark` / `html.pal-light`.
Opening palette: `?palette=NAME`; the visitor's pick for this deck (the
menu's swatches, saved per deck in localStorage `palette:/deck/`, so
each lecture in a series keeps its own); `"palette"` in meta.json
(`"pdfPalette"` in export); the form's default. `"formOptions":
["graphite"]` adds `form-opt-graphite` to `<html>` (Fair Copy's
graphite headings). Palettes, in the menu's order: light silver-navy,
silver-claret, burgundy, slate, cream-oxblood, petrol, terracotta,
silver-lamp; dark navy-gold, charcoal-brass, charcoal-coral, plum-rose,
claret-gold, slate-silver. Burgundy, slate, petrol and terracotta take
the Colourful themes' colours (those themes stay as they are, typeface
and all). To change a palette, edit the table in
scripts/build-palettes.py and run it: it rewrites palettes.css and
reports any text/ground pairing that falls short (4.5:1; the
terracotta divider is title-size, 3:1).

Forms: Plate and Key (plate; silver-navy / navy-gold), Fair Copy
(fair-copy; slate / charcoal-coral), Attested Forms (attested;
silver-claret / navy-gold), Thumb Index (thumb; petrol / claret-gold),
Quiet Index (thumb-quiet; cream-oxblood / charcoal-brass), Lantern
Slide (lantern; silver-lamp / claret-gold). The menu's palette swatches
(paper with the accent in the lower half) show only while a form is the
theme. The design record is in `994 Agents/2026-10-30-mga-slides-build/5b-design/`.
Changed after Marc's review (1 Nov): Fair Copy's body is 46px (was 54)
and its list items take a quiet en dash rather than hanging out of
their own text; a Plate and Key blockquote in running text has the
quotation mark in the margin, like one in a split layout's text
column, instead of a rule. Teaching decks set `"transition": "fade"`.

### Theme files

Each theme file @imports base.css plus light.css or dark.css and sets
CSS custom properties. Theme-dependent furniture is driven by variables,
never by filename: `--title-logos: white|mono` (logo variants and QR
colour on title/closing slides; light.css defaults to mono, dark.css and
colourful.css to white), `--r-accent` (the menu highlight),
`--r-contrast-bg/--r-contrast-ink` (@slide contrast).

The Colourful themes (Terracotta, Burgundy, Slate, Petrol) share
`colourful.css`: tinted paper, headings and bold in a deepened ink, a
full-colour ground on title/closing/contrast slides. Each is a short file
setting --c-ground, --c-ink, --c-paper, --c-title-sub, --c-title-rule,
--c-contrast-ink and the four font variables (see th-l-terracotta.css).
Colour reaches the content slides too: list dashes and numbers in
a tint of the ink, progress bar in the ground, booktabs-style table rules
in the ink, quotation rule and mark tinted, and @section dividers on the
full ground with a white heading. Small caps: Butterick's faces, Premiera
and Century Supra space their own small caps, so no tracking is added;
a face that does not (Bitter) sets --sc-tracking in its theme.
High Accessibility (th-l-acc.css) uses the same structure with Luciole,
cream paper and a navy ground; sizes match every other theme so a deck
reads identically in it. Oldstyle figures everywhere, in every theme:
never set the `font-variant` shorthand (it resets figures to lining);
use `font-variant-caps` for small caps.

Figures: oldstyle in running text and headings; data tables use lining
tabular figures (title-slide metadata tables stay oldstyle). `^^...^^`
sets all-small-caps, so it works for tags and acronyms written in
capitals (^^INTJ^^). `.md-source` is smaller, upright, right-aligned,
subtle. refitSlides suspends transitions while it measures (reveal
animates fragment font sizes) and measures hidden slides by unhiding
their stacks; it skips overview mode and refits on leaving it.

Grammar colours (.subject, .predicator, .object, .complement,
.adverbial; variables --g-* in base.css, the dark set in dark.css and
palettes.css) were chosen in Oct 2026 to stay apart under red-green
colour blindness: light Subjects #0303B5, Predicators #9C3A0A, Objects
#057B89, Complements #8448F4, Adverbials #A88200; dark #4F8BFF,
#FF7A45, #1FB59F, #C9B6FF, #F2D23C. They separate on the blue/yellow
axis and on lightness, which dichromats still see. All read at 4.5:1 on
every paper except the gold Adverbials (3:1 or better, the large-text
standard), so coloured functions in @passage are bold. Themes never
override them. Colour is the only cue, by design.

Menu sections: Forms (above); Colourful (Terracotta, Burgundy, Slate, Petrol); Classic
(Cream, Cream Sans, Cream Serif, Manuscript, Twilight, Charcoal; Cream
Serif is Cream with Equity body text, made for the 1A Meaning and
Structure lectures; Charcoal is dark, for Story of Linguistics: the
2026-27 decks' charcoal, off-white, coral and pale gold, with Equity
small-caps headings, Concourse Book body, small-caps table heads, and
==x== drawn as gold words rather than a highlight ground); Other (High Accessibility); Institutional (University of Glasgow, Historical
Thesaurus, Historical Thesaurus Cream). Racing Green, Midnight and
Letterpress were retired 2026-09 (files in _to_delete/retired/).

The menu ("m" key, or the barely-there disc bottom-left on touch
devices) uses a quiet editorial style defined in base.css: paper panel
set in Century Supra, a top band with the jackdaw (a link home to the
directory page), small-caps Concourse footer tabs, monochrome states
with the theme accent as the one colour.

### Layouts (retired 2026-10)

Every deck uses the Standard arrangement; the forms took over the
layouts' job. Spine, Masthead and Classical (and layout-standard.css,
which added nothing) are in _to_delete/retired/; head.js no longer
reads `?layout=`, a saved layout or `"layout"` in meta.json. The
--L-ground/--L-on-ground variables in base.css and fitColumnHeadings in
directives.js are left in place, unused.

`@note text` (one line) is a sidenote: a small quiet paragraph with a
hairline. After a list that animates in, it joins the step of the list
item before it (syncNoteFragments, directives.js) rather than showing
from the start.

### Builds

The MgaBuilds plugin (directives.js), registered in revconfig.js
straight after RevealMarkdown, adjusts the rendered slides before reveal
first counts their fragments: list builds per `listBuild`, `@slide
static` and `@slide build`; `@pause` groups; `@note top` placement; and,
on slides with groups or stepped blocks (`[data-md-steps]` holding
`[data-md-step="k"]`, for directives from phase 2), explicit fragment
indices in reading order, so a block's steps come after the list items
before it. `@slide build=auto` steps through the slide's builds on a
timer. `html.mga-build-appear` (from `"buildStyle": "appear"`) turns off
fragment transitions.

### Offline

`sw.js` (registered by head.js, never on localhost) keeps copies of
everything a deck uses: once a deck has been opened online, it works
with no connection. Each deck posts its full file list to the worker
when ready (every image in the deck, every video and poster, all loaded
files, the Colourful themes' stylesheets and faces). Text files are
network-first with a 4s timeout, so edits appear at once; images, fonts
and videos are cache-first, and a request for part of a stored video (a
byte range, which Safari always asks for) is answered from the stored
file.
Change `VERSION` in sw.js to discard all stored copies.

Fonts are self-hosted WOFF2 (Concourse, Equity, Century Supra by Matthew
Butterick; Premiera (Burgundy, Petrol); Bitter, OFL, variable (Slate; version 3.021, the same file as Bitter Pro's variable font, with small caps, oldstyle figures and Cyrillic);
Bild by DJR, variable (was Marginalia's; now unused);
Monaspace Neon (slide code); JetBrains Mono (handout code); Luciole for
accessibility; Noto Sans 2.000 for the University of Glasgow theme, as
"Noto Sans UoG" in woff2/noto-sans/ (OFL; unmodified, the build installed
on Marc's Mac; subset to Latin, Greek, Cyrillic and IPA). Noto Sans/Serif from Google Fonts is linked from head.js
without blocking the page, as a glyph-coverage fallback (IPA and phonetic
symbols, non-Latin). A Font Awesome 5 Duotone subset is self-hosted for
content icons (`<i class="fad fa-code"></i>`). fa-duotone-900.woff2 holds
Marc's whole licensed Font Awesome 5 Duotone set (about 3,700 icons), so
any of them may be used: add the codepoint pair in base.css
(`.fa-NAME::before { content: '\fXXX' } .fa-NAME::after { content:
'\10fXXX' }`). Agents converting decks may choose freely from it.

## Conventions for AI assistants

- Converting or writing a deck: the mga-slides skill carries the method
  (sources, converters in the build folder's phase6/tools/ and
  phase6b/tools/, the checks, meta.json per series, copying into the
  repository). This file stays authoritative for syntax.
- Converting a deck: reproduce the original, then list at the end of the
  report the slides that would work better with another construction,
  with one line each on what it would change for the room. Revising a
  deck: propose those changes first and build once Marc agrees. Never
  change what a slide says, only how it is shown. Strong constructions
  to offer: @parse steps (words never move; the whole analysis on one
  slide, a click per stage, as in 1a/6) instead of copied slides
  with labels added; @marks and @zoom instead of annotated screenshots;
  {++ -- ~~ ==} inline changes and {answer} on one slide instead of
  slide runs; @set with @menu for orientation in long topics; morpheme
  words and @slide morph where the motion explains; @cards (arrows,
  stack, accent) for comparisons and scales; @card ex for example
  sentences; @kwic build=context; @transcript overlay; @image hold for
  a chart under changing commentary; @video for explanatory motion.
  Weak here: hand-placed boxes, rotated text, decorative motion, more
  than about eight list items. (reference/index.html,
  "Designing for the framework", has the full table.)

- Use the @-directives for all image slides; do not hand-write layout divs
  or inline font-size styles in markdown.
- Always provide alt text in directives.
- Use relative paths (../inc/, ./img/) everywhere.
- Test locally before committing; check the browser console.
- Don't modify vendored reveal.js core; don't add build steps or npm
  packages; don't touch CNAME; archive presentations rather than deleting.
- Commit messages: descriptive, e.g. "Add icame47 presentation",
  "Fix zoom positioning for portrait images".
- Optimise images before adding (target under 500KB each).
- Presentations may address sensitive academic topics; keep the tone
  professional and include content advisories where appropriate (see the
  archived dsna25 for an example).
